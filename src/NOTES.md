تمرین جمع‌بندی useEffect

۱. محاسبه fullName از firstName و lastName

Effect لازم نیست.

چون fullName یک مقدار محاسباتی است و از داده‌هایی که از قبل داریم به دست می‌آید. بنابراین می‌توانیم آن را مستقیماً در زمان رندر محاسبه کنیم.

⸻

۲. فیلتر کردن محصولات

Effect لازم نیست.

چون نتیجه فیلتر کردن محصولات از داده‌های موجود به دست می‌آید و نیازی به هماهنگ شدن با یک سیستم خارجی نداریم. این مقدار یک داده محاسباتی است.

⸻

۳. ارسال درخواست API هنگام تغییر userId

Effect لازم است.

چون با تغییر userId باید اطلاعات جدید از API دریافت شود. API یک سیستم خارج از React است و Effect برای هماهنگ کردن کامپوننت با سیستم‌های خارجی استفاده می‌شود.

⸻

۴. تغییر عنوان صفحه با document.title

Effect لازم است.

چون document.title مربوط به محیط مرورگر و خارج از React است. بنابراین برای هماهنگ کردن عنوان صفحه با State یا Props از Effect استفاده می‌کنیم.

⸻

۵. مدیریت کلیک دکمه

Effect لازم نیست.

چون کلیک یک رویداد مستقیم کاربر است. کاری که باید هنگام کلیک انجام شود، بهتر است داخل تابع مربوط به همان رویداد انجام شود، نه داخل useEffect.

⸻

۶. ذخیره مقدار در localStorage

Effect لازم است، وقتی هدف همگام‌سازی مقدار با localStorage باشد.

چون localStorage خارج از React قرار دارد و برای هماهنگ کردن مقدار State با آن می‌توان از Effect استفاده کرد.

البته اگر ذخیره کردن مقدار مستقیماً در پاسخ به یک کلیک یا رویداد خاص انجام شود، می‌توان آن را داخل همان تابع رویداد انجام داد و نیازی به Effect نیست.

⸻

جمع‌بندی

به طور کلی، قبل از استفاده از useEffect باید از خودمان بپرسیم:

آیا داریم چیزی را با یک سیستم خارج از React هماهنگ می‌کنیم؟

اگر فقط در حال محاسبه کردن داده، فیلتر کردن، یا پاسخ دادن مستقیم به یک رویداد کاربر هستیم، معمولاً نیازی به Effect نداریم.

اما اگر با چیزهایی مثل API، DOM مرورگر، تایمر، Event Listener یا localStorage در حال هماهنگ شدن هستیم، Effect می‌تواند لازم باشد.
